## 3. Measurement method

A dependency-free Node script (`apps/web/scripts/measure-bundle-size.mjs`, built-ins only:
`fs`/`path`/`zlib`) reads the **actual generated artifacts** under `apps/web/.next` after the
clean build above — it does not estimate, does not read from `next build`'s console output (which,
under Turbopack, no longer prints the old webpack-era per-route "First Load JS" table), and does
not require the dev/build process to still be running.

- **Total JS/CSS sizes**: every `.js`/`.css` file directly under `.next/static/chunks` (exactly
  what a browser fetches) is read, gzipped (`zlib.gzipSync`, level 9) and Brotli-compressed
  (`zlib.brotliCompressSync`, quality 11) to get raw/gzip/Brotli sizes per file.
- **Route-level estimates**: each route's `page_client-reference-manifest.js` under
  `.next/server/app/**` (Next's own React Server Components module→chunk map, generated by the
  build itself) is parsed to get the exact set of chunk files that route's client module graph
  references, then those chunks' sizes are summed. This is the same underlying concept the
  old webpack "First Load JS" column measured — see §9 for why it is an estimate, not identical.
- **Attribution**: content-based, not filename-based (per instruction) — see §7.

## 7. MapLibre attribution evidence

Not claimed from chunk size alone (per instruction). Three independent pieces of evidence:

1. **Content strings.** `1qdrcq8i0bp_v.js` contains the literal string `maplibregl`, the WebGL
   vertex shader source `attribute vec2 a_pos` (a real internal MapLibre GL JS shader attribute
   name), and `RTLTextPlugin` (MapLibre's right-to-left text rendering plugin) — none of these
   appear in any other chunk.
2. **Route-manifest cross-reference.** This exact chunk is referenced by `/map` and `/explore`'s
   `page_client-reference-manifest.js` and **absent** from `/hotels`, `/search`, and `/dashboard`'s
   — confirmed by direct `grep` against all five manifests, not assumed.
3. **Dependency inspection.** `apps/web/package.json` lists exactly one client-side mapping
   library (`maplibre-gl@^4.5.0`), and it is imported by exactly one component
   (`apps/web/src/modules/map/MapView.tsx`), which is in turn only rendered by `/map`'s page and
   `/explore`'s `SearchMapExplorer` — matching evidence #2 exactly.

All three agree. MapLibre GL JS is confirmed as the dominant contributor to `1qdrcq8i0bp_v.js`,
and by extension to `/map` and `/explore`'s outsized route estimate.

## 9. Measurement limitations

- **Route-level estimates are an approximation, not an exact reproduction of a metric Next.js
  still prints.** Turbopack's `next build` output (Next 16) no longer prints the old webpack-era
  per-route "First Load JS" table this repository's earlier informal bundle mentions (PLACE-041)
  were implicitly comparable to. The `page_client-reference-manifest.js`-based method used here
  captures the same underlying concept (all chunks a route's client module graph needs) but was
  independently derived from Next's own build manifests, not validated against an official Next
  CLI output for this exact Next/Turbopack version.
- **Two mid-size chunks could not be attributed with confidence** (`10lzwjioi-7jo.js` 138.4 KB,
  `0cz1d0mv5g_q7.js` 110.0 KB) — the content-marker list used (§3) did not include enough
  Next.js-internal signatures to positively identify them. Most likely Next.js/React Server
  Components client runtime internals (they appear in every route's `rootMainFiles`, per
  `build-manifest.json`), but this is disclosed as unattributed rather than guessed.
- **Gzip/Brotli figures are computed locally via Node's `zlib`** at fixed quality settings, not
  measured from an actual HTTP response through the production reverse proxy (Caddy). They are a
  standard, reasonable approximation of what compression would achieve, not a live network capture
  — actual served sizes depend on Caddy's real compression configuration, which was not inspected
  as part of this frontend-only measurement task.
- **Source-map count (192)** includes 169 unique server-side maps plus 23 duplicates under
  `.next/standalone/` (the Docker-packaging output copy) — confirmed by path inspection, not
  estimated. Zero are under `.next/static` (client-shipped).

## 11. Advisory regression thresholds

**Advisory only. Not a CI gate. Not enforced anywhere in this repository. Subject to Owner
approval before any enforcement mechanism is ever added.** Chosen from the measured baseline
above, not arbitrary:

- Warn if **total client JS gzip** increases by more than 10% from baseline (420.7 KB → investigate
  above ≈ 463 KB).
- Warn if **any route's estimated JS gzip** increases by more than 15% from its own baseline (e.g.
  `/map`/`/explore`: 223–224 KB → ≈ 257 KB; the six non-map routes: ~16–20 KB → ~19–23 KB).
- Warn if the **largest single chunk** increases by more than 10% (203.7 KB gzip → ≈ 224 KB).
- Investigate any **newly introduced chunk above 50 KB raw** — chosen because the current chunk
  list drops from 138.4 KB straight down into a long tail under 55 KB (§5); a new chunk at or above
  that size would represent a meaningfully new dependency or module, worth a deliberate look before
  merging.
