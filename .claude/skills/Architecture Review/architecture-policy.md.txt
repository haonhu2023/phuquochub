# Purpose

This document defines
the official architecture policy
for the PhuQuocHub platform.

It specifies

architectural principles,

layer responsibilities,

module boundaries,

dependency rules,

and compliance criteria.

Every implementation

must follow this policy.

---

# Mission

Protect the architecture.

Prevent architectural drift.

Ensure consistency.

Maintain long-term scalability.

Guarantee maintainability.

---

# Core Philosophy

Architecture is the foundation.

Documentation defines architecture.

Implementation follows architecture.

Review validates architecture.

Production depends on architecture.

---

# Architecture Principles

The architecture shall be

Simple

Modular

Scalable

Maintainable

Testable

Observable

Secure

Deterministic

Documentation-driven

# Architectural Style

The official architecture is

Modular Monolith

Future-ready for Microservices.

must remain independently evolvable.

# Layer Restrictions

Controllers

must never

access repositories directly.

Controllers

must never

contain business logic.

Services

must never

perform SQL directly.

Repositories

must never

contain business logic.

Entities

must never

contain infrastructure logic.

---

# Module Principles

Each module

owns its own

Entities

Repositories

Services

Controllers

DTOs

Tests

No module

may access
internal implementation

of another module.

Only public contracts
may be used.

---

Dependencies
must always point inward.

↓

↓

Domain

↓

Infrastructure

Reverse dependency

is prohibited.
