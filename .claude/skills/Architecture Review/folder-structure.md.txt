# Purpose

This document defines

the official repository folder structure

for the PhuQuocHub platform.

Every directory

must have

a documented purpose.

Every file

must belong

to a documented location.

Folder organization

must remain

stable,

predictable,

and scalable.

---

# Mission

Maintain

repository consistency.

Prevent

folder drift.

Guarantee

module discoverability.

Support

long-term maintainability.

---

# Core Principles

Every folder

has one responsibility.

Every module

owns its own directory.

Shared components

remain isolated.

Infrastructure

is separated

from business logic.

Documentation

is separated

from implementation.

---

# Repository Root

The repository root

contains only

apps/

packages/

docs/

scripts/

tests/

tools/

configs/

docker/

.github/

assets/

No undocumented

top-level directory

is allowed.

---

# apps/

Contains

deployable applications.

Examples

apps/api

apps/web

apps/admin

apps/mobile

Rules

Each application

must be

self-contained.

---

# packages/

Contains

shared libraries.

Examples

packages/common

packages/config

packages/logger

packages/types

packages/utils

packages/database

Rules

Packages

must never

depend on feature modules.

---

# docs/

Contains

the Single Source of Truth.

Examples

api/

data/

security/

workflow/

standards/

overview/

99-decisions/

Rules

Documentation

must never

contain implementation.

---

# scripts/

Contains

automation scripts.

Examples

migration

seed

backup

restore

release

ci

Rules

Scripts

must not

contain business logic.

---

# tests/

Contains

cross-module tests.

Examples

integration

e2e

performance

security

Rules

Unit tests

remain

inside modules.

# docker/

must be centralized.

# .github/

actions

dependabot

# assets/

images

must use

kebab-case

spaces

# File Naming Rules

Files

must use

kebab-case

Examples

---

# Module Isolation

Each module

owns

its folders.

Cross-module access

must occur

through

public services

or

documented interfaces.

Direct access

to another module's

internal folders

is prohibited.

---

Improper nesting

Shared code

inside feature modules

Feature code

inside shared packages
