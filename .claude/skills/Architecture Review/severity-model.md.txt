# Purpose

This document defines

the official Severity Model

for the PhuQuocHub platform.

Severity determines

the impact,

priority,

urgency,

approval status,

and release readiness

of every finding.

All reviews

must classify

every issue

using this model.

---

# Mission

Provide

a consistent,

objective,

repeatable,

and evidence-based

severity classification

across the entire project.

---

# Core Principles

Severity

measures impact,

not effort.

Severity

must always

be evidence-based.

Severity

must never

depend on opinion.

Severity

must be

repeatable.

Severity

must be

deterministic.

---

# Escalation Rules

A finding

must be escalated

if

Multiple Medium

combine

into one High.

Multiple High

combine

into one Critical.

Repeated unresolved issue

appears

across

three consecutive Sprints.

Security issue

affects

authentication

authorization

database integrity

or production deployment.

---

# Downgrade Rules

Severity

may only

be downgraded

if

Evidence proves

lower impact.

Architecture owner

approves.

Documentation updated.

Review repeated.

Never downgrade

without evidence.
