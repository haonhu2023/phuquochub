# Purpose

This document defines the milestone policy
for the PhuQuocHub project.

Milestones provide measurable checkpoints
throughout the software lifecycle.

Every Sprint contributes
to one or more milestones.

No milestone may be declared complete
without satisfying its acceptance criteria.

---

# Core Principle

A milestone is not based on time.

A milestone is based on completed outcomes.

Never declare completion
because a date has arrived.

Declare completion
only when evidence exists.

---

# Blocking Conditions

A milestone cannot be completed if

Architecture Drift exists

Documentation Drift exists

Critical Security Issue exists

Migration Failure exists

CI is failing

Production Gate failed

Required Sprint not accepted

---

# Technical Debt Policy

Technical debt may carry forward
only if

Risk is Medium or Low

Owner assigned

Target Sprint defined

Mitigation documented

Critical debt

blocks milestone completion.

---

# Dependency Rules

Every milestone

must depend only on

completed milestones.

Example

M3 depends on

M2 completed.

M5 depends on

M4 completed.

Never skip dependencies.
