# Purpose

This document defines the mandatory merge policy
for the PhuQuocHub project.

A merge is the official acceptance
of implementation into the project's history.

No code shall be merged
without satisfying every required quality gate.

---

# Core Principle

Merge is a business decision,
not merely a Git operation.

Code generation does not imply merge approval.

Every merge must preserve

Architecture

Documentation

Code Quality

Security

Production Stability

Lint fails

Migration fails

Rollback fails

OpenAPI changes without ADR

Decision Register conflict exists

Documentation Freeze violated

---

# Conditional Merge

A conditional merge may be allowed only if

Risk Classification

Medium or Low

AND

Technical Debt documented

AND

Owner approval recorded

Conditional merge is prohibited
for Critical or High risks.

---

# Technical Debt Merge

Technical debt must be classified.

Critical

Merge prohibited

High

Merge prohibited

Medium

Merge allowed only with tracking issue

Low

Merge allowed

Every accepted debt
must include

Description

Impact

Mitigation

Target Sprint

Owner

---

# Documentation Merge

Documentation must be merged together with code
whenever implementation changes documentation.

Never allow

Code merged

Documentation pending

unless explicitly approved by ADR.

# Rollback Policy

Every merge must be reversible.

Rollback must

Restore previous state

Preserve database integrity

Restore API compatibility

Restore production stability

Rollback plan must exist
before merge.
