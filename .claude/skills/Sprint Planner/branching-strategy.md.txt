# Purpose

This document defines the Git branching strategy
for the PhuQuocHub project.

Every implementation must follow
a predictable branch lifecycle.

Branches must reflect
the project roadmap,
Sprint structure,
and release strategy.

No work shall be performed
directly on protected branches.

---

# Core Principle

Every change begins in an isolated branch.

Every branch has one responsibility.

Every branch is short-lived.

Every branch is traceable.

# Branch Types

## Production

Name

production

Purpose

Live production deployment.

Requirements

Production Gate PASS

Deployment verified

Rollback verified

Monitoring active

---

## Release

Format

release/vX.Y.Z

Example

release/v1.0.0

Purpose

Release candidate.

Requirements

Sprint Acceptance PASS

Architecture PASS

CI PASS

---

## Main

Name

main

Purpose

Stable codebase.

Every commit

must be releasable.

---

## Develop

Name

develop

Purpose

Integration branch.

All accepted Sprint branches merge here first.

---

## Sprint

Format

sprint/sprint-01-auth

sprint/sprint-02-places

sprint/sprint-03-hotels

Purpose

Complete Sprint implementation.

Contains

multiple Feature branches.

Deleted after merge.

---

## Feature

Format

feature/place-search

Single feature implementation.

Scope

One Batch only.

Format

## Hotfix

Format

# Success Criteria

The Branching Strategy succeeds when

every implementation,

every Sprint,

and every Release

can be traced
from Documentation Freeze
to Production.

Git history remains

clean,

predictable,

reviewable,

and reproducible.

No work is ever lost,

no change is ever untraceable,

and every release
can be rolled back safely.
