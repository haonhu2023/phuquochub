# Purpose

This document defines the dependency graph
for the entire PhuQuocHub platform.

Its purpose is to ensure that

every Sprint,

every Batch,

every module,

every service,

and every database object

is implemented
in the correct order.

Claude Code must never
implement a module
before all of its required dependencies
have been accepted.

---

# Core Principle

Dependencies determine implementation order.

Implementation order
must never be guessed.

Dependencies are part of the architecture.

Changing dependencies
requires ADR.

# Dependency Rules

A dependency

must already exist

must already compile

must already pass review

must already be accepted

before a dependent module
may be implemented.

# Batch Rules

A Batch may contain

only modules

whose dependencies
have already passed acceptance.

Never mix

Infrastructure

and Business Logic

in the same Batch.

---

# Dependency Validation

Before generating code

Claude Code must verify

Dependencies exist

Dependencies accepted

Dependencies documented

Dependencies compile

Dependencies tested

Dependencies merged

---

# Circular Dependency Rules

Circular dependency

is prohibited.

If detected

Stop immediately.

Report

BLOCKER

Do not generate code.

---

# Missing Dependency

If dependency

does not exist

Report

NOT FOUND

Do not invent.

Do not bypass.

Do not create automatically.

---

# Dependency Reporting

Every Sprint Plan

must include

Dependency Graph

---

# Dependency Decisions

Only three states

READY

BLOCKED

NOT FOUND

No other status.

---

# Success Criteria

Dependency Graph succeeds when

every module

every service

every entity

every API

every Sprint

is implemented

in the correct order,

without circular dependency,

without undocumented assumptions,

and without violating

the frozen architecture.
