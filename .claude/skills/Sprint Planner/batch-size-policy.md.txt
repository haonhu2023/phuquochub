# Purpose

This document defines the maximum allowable size
for an implementation batch.

The purpose is to ensure that every generated batch is

- reviewable
- testable
- understandable
- mergeable
- reversible

Large batches increase

- review complexity
- architecture drift
- merge conflicts
- regression risk

Therefore Claude Code must automatically split
large implementation tasks into multiple batches.

---

# Core Principle

A batch should be as small as possible,
but large enough to provide measurable progress.

Small batches reduce risk.

Large batches increase uncertainty.

Never optimize for Lines of Code.

Always optimize for review quality.

# Automatic Split Rules

Claude Code must split a batch if

Files >15

OR

LOC >1000

OR

Complexity Score >35

OR

Touches multiple modules

OR

Touches unrelated layers

OR

Changes architecture

# Parallel Execution Rules

Batches may execute in parallel only if

No shared entities

No shared migrations

No shared repositories

No shared APIs

No shared DTOs

No shared permissions

Otherwise

Sequential execution is required.

# Success Criteria

A batch size policy succeeds when

Every generated batch

can be reviewed within one sitting,

merged independently,

reverted independently,

and implemented without architectural decisions.

Batch size must maximize

quality,

traceability,

and maintainability,

not generation speed.
