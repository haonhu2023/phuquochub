# Purpose

This document defines

the official Consistency Rules

for the PhuQuocHub platform.

Consistency Rules

ensure

every authoritative artifact

remains synchronized,

internally consistent,

and fully traceable.

These rules

prevent

Architecture Drift,

Documentation Drift,

Database Drift,

API Drift,

Workflow Drift,

Repository Drift,

and Implementation Drift.

---

# Mission

Guarantee

that every layer

of the platform

describes

the same system,

using

the same terminology,

the same structure,

the same contracts,

and the same business rules.

---

# Fundamental Principle

Consistency

means

every artifact

describes

exactly

the same reality.

If

two authoritative artifacts

describe

different realities,

the repository

is inconsistent.

# Rule Group 1

Architecture Consistency

Architecture

must be consistent

with

ADR

Decision Register

Domain Model

Component Diagram

Container Diagram

Context Diagram

No component

may exist

outside

Architecture.

---

# Rule Group 2

ADR Consistency

Every ADR

must

reference

Architecture.

Every ADR

must

appear

inside

Decision Register.

Superseded ADRs

must remain

archived.

No active ADR

may contradict

another active ADR.

---

# Rule Group 3

Decision Register Consistency

must reference

Architecture

ADR

Affected Modules

Affected Documents

Approval Date

Owner

Status

# Rule Group 4

Database Documentation Consistency

Database Documentation

must match

ERD

Data Dictionary

Prisma Schema

Database Migrations

Entities

Indexes

Constraints

Relationships

Naming Convention

No undocumented

table

column

constraint

or index

is permitted.

---

# Rule Group 5

Prisma Consistency

Prisma Schema

must match

Database Documentation.

Every model

must have

a documented table.

Every relation

must exist

inside ERD.

---

# Rule Group 6

Migration Consistency

Every migration

must

implement

approved documentation.

Migration

must never

introduce

undocumented objects.

Migration history

must remain immutable.

---

# Rule Group 7

OpenAPI Consistency

Every endpoint

must exist

inside

OpenAPI.

Every request DTO

must match

OpenAPI schema.

Every response DTO

must match

OpenAPI schema.

Every validation rule

must match

OpenAPI.

must implement

# Rule Group 16

Documentation Consistency

All documentation

must

The same concept

Circular references
