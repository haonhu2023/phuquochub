# Purpose

This document defines

the official Repository Policy

for the PhuQuocHub platform.

The Repository

is the physical implementation

of the approved architecture.

It must remain

organized,

predictable,

maintainable,

modular,

traceable,

and fully compliant

with the Single Source of Truth (SSOT).

The Repository

implements

documentation.

It never

defines

documentation.

---

# Mission

Provide

a consistent,

scalable,

enterprise-grade

repository structure

that supports

long-term development,

AI-assisted coding,

automated reviews,

continuous integration,

continuous deployment,

and architectural governance.

---

# Fundamental Principle

Repository

must always

reflect

approved documentation.

Repository

must never

become

the authoritative source.

Whenever

Repository

and Documentation

differ,

Documentation

wins.

# Module Rules

Every module

must have

One Responsibility

One Owner

One Public Interface

One Documentation Reference

One Test Strategy

One Dependency Boundary

---

# Dependency Rules

Modules

may depend

only

on approved layers.

Dependencies

must follow

Architecture.

Circular dependencies

are prohibited.

Reverse dependencies

are prohibited.

Hidden dependencies

are prohibited.

---

# Layer Rules

Presentation

↓

Application

↓

Domain

↓

Infrastructure

Dependencies

must flow

downward only.

---

# Import Rules

Modules

must import

through

public interfaces.

Deep imports

are prohibited.

Private modules

must never

be imported

externally.

---
